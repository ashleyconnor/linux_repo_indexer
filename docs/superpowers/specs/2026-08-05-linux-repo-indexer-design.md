# Linux Repository Indexer — Design

*Status: approved, 2026-08-05*

## Context

Today the apt and yum repositories at `apt.releases.hashicorp.com` / `rpm.releases.hashicorp.com` are generated by Artifactory (`Origin: Artifactory` in every `Release` file). Artifactory rescans packages to rebuild indexes, which is the expensive, badly-scaling part.

We are replacing that with a serverless indexer: packages live in S3, normalized package metadata lives in DynamoDB, and index files are generated from the database — never by re-reading packages. A package is parsed exactly once, when it is uploaded.

The existing repositories must be reproduced faithfully enough that existing clients keep working, so an existing-index seeder is a first-class deliverable, not an afterthought.

### Confirmed layout (verified against the live repos)

**apt** — one shared pool, fanned out to every codename:
```
pool/<arch>/<component>/<name>_<version>_<arch>.deb
dists/<codename>/<component>/binary-<arch>/Packages{,.gz,.xz}
dists/<codename>/<component>/binary-<arch>/by-hash/{SHA256,SHA1,MD5Sum}/<hash>
dists/<codename>/{Release,Release.gpg,InRelease}
```
`jammy`, `noble`, `bookworm`, `trixie` all list the identical 3426 packages with identical `Filename:` values — the pool is codename-independent. `Acquire-By-Hash: yes` is set, so `by-hash/` must be published.

**yum** — self-contained tree per distro/version/arch/channel, RPMs flat at the root:
```
<Distro>/<version>/<arch>/<channel>/<name>-<ver>-<rel>.<arch>.rpm
<Distro>/<version>/<arch>/<channel>/repodata/{repomd.xml,repomd.xml.asc,<hash>-primary.xml.gz,<hash>-filelists.xml.gz,<hash>-other.xml.gz}
```

### Decisions

| Area | Decision |
|---|---|
| Language | Go, `provided.al2023` on arm64 |
| Metadata store | DynamoDB (`packages`, `repo_state`) |
| Publish model | Coalesced: ingest marks scope dirty + bumps generation; publisher leases the scope and rebuilds |
| Signing | GPG key from Secrets Manager (KMS cannot do OpenPGP) |
| Seeding | Parse existing `Packages.gz` / `primary.xml.gz` — no package downloads |
| Repo config | `repos.yaml` object in S3 — adding/removing distros is a config edit |
| IaC | Terraform, same modules for LocalStack and AWS |
| Retention | Keep all versions; `ObjectRemoved` events delete rows |
| Metadata format | Modernised: SHA256 repomd checksums, `Packages{,.gz,.xz}`, `by-hash` kept, `.bz2` dropped |
| v1 scope | `noble` + `RHEL/9`, `amd64`/`arm64` (`x86_64`/`aarch64`), both `main`/`stable` and `test` channels |
| E2E | testcontainers-go: LocalStack + `ubuntu:24.04` + `registry.access.redhat.com/ubi9/ubi` |

## Architecture

```
S3 ObjectCreated/ObjectRemoved
        │
        ▼
   SQS ingest queue ──► ingest Lambda
                          ├── parse .deb/.rpm (single streaming pass, hashing as it reads)
                          ├── PutItem into packages
                          ├── ADD generation 1 on repo_state
                          └── enqueue publish message (DelaySeconds ≈ 30, coalescing window)
        │
        ▼
   SQS publish queue ──► publish Lambda
                          ├── acquire scope lease (conditional write, TTL)
                          ├── read generation g; skip if g == publishedGeneration
                          ├── Query all packages in scope
                          ├── build artifacts (pure functions)
                          ├── sign, write to S3, prune stale by-hash/repodata
                          └── set publishedGeneration = g, release lease

   EventBridge rate(5 min) ──► publish Lambda (sweeper: republish any scope left dirty)
```

### Why the lease

Two publishers racing on one scope can otherwise write a stale index while recording a newer generation (A reads at g=5, B reads at g=7, B writes, A overwrites). A conditional-write lease on `repo_state` with a TTL serializes per scope; a publisher that cannot acquire the lease returns its message to the queue, and the current holder picks up the newer generation anyway.

### Scopes

Storage scope is what a package belongs to. Publish scope is what gets written.

| Kind | Key | Notes |
|---|---|---|
| deb pool | `deb/<component>/<arch>` | Codename-independent — matches the shared pool |
| deb release | `release/<codename>` | Assembles `Release`/`InRelease` from recorded per-scope artifact digests |
| rpm tree | `rpm/<distro>/<version>/<arch>/<channel>` | Self-contained |

Publishing a `deb/<component>/<arch>` scope writes the `Packages*` files into **every** codename mapped to that (component, arch) in `repos.yaml`, records each artifact's size/MD5/SHA1/SHA256 on the scope's `repo_state` item, then enqueues `release/<codename>` for each. The release publisher reads those recorded digests — it never re-reads S3 to build `Release`.

## Repository structure

```
go.mod                                  module github.com/ashleyconnor/linux-repo-indexer
cmd/
  ingest/main.go                        Lambda: SQS(S3 events) → metadata
  publish/main.go                       Lambda: SQS + EventBridge → index build + S3 sync
  seed/main.go                          CLI: seed, verify, diff against live index
  repoadmin/main.go                     CLI: explicit retire of a removed distro tree
internal/
  pkgmeta/package.go                    normalized Package model, EVR compare, scope derivation
  pkgmeta/deb/parse.go                  ar → control.tar.{gz,xz,zst} → control
  pkgmeta/rpm/parse.go                  RPM header → Package (+ files, changelog, header-range)
  repoconfig/config.go                  repos.yaml load/validate, key→scope mapping
  store/dynamo.go                       PutPackage, DeletePackage, QueryScope, blob overflow
  store/state.go                        generation, lease, publishedGeneration, artifact digests
  index/artifact.go                     Artifact{Path, ContentType, Body}
  index/debian/{packages.go,release.go} pure generators
  index/rpmmd/{primary.go,filelists.go,other.go,repomd.go}
  sign/{signer.go,gpg.go,noop.go}
  sync/s3sync.go                        write artifacts, prune stale by-hash / repodata
  seed/{debindex.go,rpmindex.go}        parse existing indexes back into Package records
test/e2e/                               testcontainers: pipeline + container install checks
testdata/                               fixture packages + golden index files
deploy/terraform/{modules,envs}
docs/superpowers/specs/                 design doc (write + commit as step 0)
```

The generators are pure: `BuildDebianPackages([]Package) []Artifact`, `BuildRPMRepodata([]Package) []Artifact`. They know nothing about S3, DynamoDB, or Lambda, which is what makes the golden-file tests possible.

## Data model

**`packages` table**

- PK `scope` — `deb/main/amd64` or `rpm/RHEL/9/x86_64/stable`
- SK `pkgkey` — `<name>#<evr>#<arch>`
- Attributes: `s3key`, `filename` (index-relative), `size`, `sha256`, `sha1`, `md5`, `name`, `version`, `epoch`, `release`, `arch`, `summary`, `description`, `depends`/`provides`/`conflicts`/`obsoletes`/`recommends`/`suggests`, `installedSize`, `maintainer`, `homepage`, `license`, `vendor`, `section`, `priority`, `sourceRpm`, `buildHost`, `buildTime`, `fileTime`, `headerStart`, `headerEnd`, `archiveSize`, `primaryFiles`, `filelist`, `changelog`, `controlExtra`, `updatedAt`

`filelist` and `changelog` overflow to `s3://<bucket>/.meta/pkgblob/<sha256>.json.gz` with a pointer attribute when the item would exceed ~300 KB (DynamoDB's hard limit is 400 KB; the live repo averages ~7 KB of filelist XML per package, so overflow is rare but a large kernel-style package would hit it).

**`repo_state` table**

- PK `scope`
- `generation` (N, `ADD 1` on every ingest/delete), `publishedGeneration` (N), `leaseOwner`, `leaseExpiry`, `lastPublishedAt`, `artifacts` (list of `{path,size,md5,sha1,sha256}` — consumed by the release publisher)

## repos.yaml

```yaml
version: 1
signing:
  secret_id: linux-repo-indexer/gpg-signing-key
apt:
  origin: HashiCorp
  label: HashiCorp
  pool_prefix: pool           # pool/<arch>/<component>/<file>.deb
  dists_prefix: dists
  acquire_by_hash: true
  compressions: [gz, xz]
  components: [main, test]
  architectures: [amd64, arm64]
  codenames: [noble]
rpm:
  checksum: sha256
  trees:
    - distro: RHEL
      version: "9"
      architectures: [x86_64, aarch64]
      channels: [stable, test]
```

Adding a codename/tree: add the row, next publish creates it. Removing one: delete the row and publishing stops — but the S3 tree is **not** deleted implicitly. Tearing down a retired tree requires `repoadmin retire --scope ...`, so a config typo cannot destroy a live repository.

## Ingest details

- Classify the S3 key against `repos.yaml`; unrecognised keys are logged and skipped, not failed.
- Single streaming pass: wrap the `GetObject` body in a `TeeReader` feeding MD5/SHA1/SHA256 hashers, hand the tee to the parser, then drain the remainder to `io.Discard`. The package is read once, in full, and never downloaded again.
- Debian: `github.com/blakesmith/ar` + `archive/tar` + `compress/gzip` + `github.com/klauspost/compress/zstd` (and xz) for `control.tar.*`. Control parsing including continuation lines is our own code — it is ~40 lines and the format is stable.
- RPM: `github.com/cavaliergopher/rpm` for the binary header. We additionally need the header byte range for `<rpm:header-range>`; if the library does not expose it, compute it from the lead/signature/header offsets during the same pass.
- SQS batch size 10, partial batch failure reporting so one bad package does not replay the batch.
- `ObjectRemoved:*` (including delete markers) deletes the row and bumps the generation.

## Publish details

**Debian.** Sort by name then version. Render RFC822 paragraphs preserving the original control fields plus `Filename`, `Size`, `MD5sum`, `SHA1`, `SHA256`. Emit `Packages`, `.gz`, `.xz` and their `by-hash/{MD5Sum,SHA1,SHA256}/<hash>` copies. `Release` carries `Origin`, `Label`, `Suite`, `Codename`, `Date`, `Acquire-By-Hash: yes`, `Components`, `Architectures` and the three checksum blocks; then clearsign to `InRelease` and detach-sign to `Release.gpg`.

**RPM.** `primary.xml` (full `<format>` block, provides/requires/conflicts/obsoletes, primary files, `<rpm:header-range>`), `filelists.xml`, `other.xml`; gzip each; name `<sha256-of-compressed>-primary.xml.gz`; `repomd.xml` with `type="sha256"` checksums, open-checksum, sizes, timestamp and revision; detach-sign to `repomd.xml.asc`.

**Pruning.** Old `by-hash/` entries and old `repodata/<hash>-*.gz` files are deleted only once they are both absent from the current index and older than a 7-day grace period, so apt/dnf clients mid-fetch do not 404.

**Sizing.** ~3400 packages/scope, ~24 MB of filelist data read per publish. Publisher: 2048 MB, 15 min timeout, paginated Query.

## Signing

`sign.Signer` with `ClearSign` and `DetachSign`. Implementations: `gpg` (armored private key + passphrase from Secrets Manager, cached per container, `github.com/ProtonMail/go-crypto/openpgp` — `x/crypto/openpgp` is frozen), and `noop` for unit tests. E2E generates an ephemeral key and installs its public half into the test containers.

**Ops note:** cutover must sign with the existing production key (fingerprint `798A EC65 4E5C 1542 8C8E 42EE AA16 FCBC A621 E701`), otherwise every existing client fails `apt-get update`.

## Seeding

`cmd/seed` runs locally against real AWS, concurrent, resumable, idempotent (Put overwrites), with `--dry-run`.

- **apt**: fetch one `dists/<codename>/<component>/binary-<arch>/Packages.gz` per (component, arch) — the pool is shared, so one codename is enough. The existing `Packages` already carries `SHA256`, `SHA1` and `Size`, so deb seeding is complete with no S3 reads beyond a `HeadObject` existence check.
- **rpm**: fetch `repomd.xml`, then primary + filelists + other, and join on the `pkgid` checksum.

**Known gap:** the live `primary.xml` uses SHA1 `pkgid` checksums, so seeded RPM rows have no SHA256. Resolution order: (1) `HeadObject` with `ChecksumMode=ENABLED` — free if the object was uploaded with an additional checksum; (2) otherwise keep the SHA1 as the package checksum. Mixed per-package checksum types within one `primary.xml` are legal and dnf verifies them correctly, so this is a real fallback, not a compromise. A background backfill can upgrade rows later.

`seed verify` reports rows whose S3 object is missing. `seed diff` generates indexes from the seeded database and diffs them against the currently-live index — this is the cutover gate, run before any DNS/CDN change.

## Testing

**Unit / golden.** Fixture `.deb` and `.rpm` committed to `testdata/`, with golden `Packages`, `Release`, `primary.xml`, `filelists.xml`, `repomd.xml` generated by real `apt-ftparchive` and `createrepo_c` and committed alongside. Generator tests assert byte equality modulo timestamps. Round-trip property test: `parse(generate(pkgs)) == pkgs`.

**Pipeline E2E** (`-tags e2e`, testcontainers-go). LocalStack with S3, DynamoDB, SQS, Lambda, Secrets Manager, IAM, Logs. Terraform applies the same modules against LocalStack via an `endpoints` override tfvars file (skipping with a clear message if no `terraform` binary is present), so the IaC is genuinely exercised. Then: upload fixture `.deb` to `pool/amd64/main/` and `.rpm` to `RHEL/9/x86_64/stable/` → assert DynamoDB rows and publish messages → run the publisher → assert `dists/noble/main/binary-amd64/Packages.gz`, `Release`, `InRelease`, a `by-hash/SHA256/<hash>` entry, and `RHEL/9/x86_64/stable/repodata/{repomd.xml,repomd.xml.asc}` → delete the `.deb`, republish, assert it is gone from `Packages`.

The publisher is triggered via SQS and direct invoke, never via EventBridge Scheduler, which LocalStack community does not reliably support.

**Install verification** (`-tags e2e`, separate suite). Containers join the LocalStack network and hit its path-style S3 endpoint directly — apt appends `dists/...` and dnf appends `repodata/...` to the base URL, so no extra static file server is needed.

- `ubuntu:24.04`: install the test public key to `/usr/share/keyrings/`, write a `signed-by=` sources entry, `apt-get update`, `apt-get install -y <fixture>`, assert the binary runs. Proves the `InRelease` → `Packages` → `.deb` checksum chain end to end.
- `registry.access.redhat.com/ubi9/ubi` (pullable unauthenticated, dnf-identical to RHEL 9): `rpm --import` the test key, write `/etc/yum.repos.d/` with `repo_gpgcheck=1` and `gpgcheck=0`, `dnf install -y <fixture>`, assert the binary runs. Proves `repomd.xml.asc` and the primary/filelists chain. `gpgcheck=0` because the fixture RPM is not package-signed — package signing is the build system's job, not this service's.

CI: `go test ./...` on every push; `-tags e2e` on a Docker-enabled runner.

## Implementation order

Each phase ends green and independently reviewable.

1. **Model + parsers.** `pkgmeta` + deb/rpm parsers, fixture packages, parser tests. No AWS.
2. **Generators.** `index/debian` + `index/rpmmd` as pure functions; golden tests against `apt-ftparchive` / `createrepo_c` output. This is the correctness core — do not move on until goldens match.
3. **Config + store.** `repoconfig`, `store/dynamo`, `store/state` (generation, lease, artifact digests), tested against LocalStack.
4. **Lambdas.** `cmd/ingest`, `cmd/publish`, `sync/s3sync`, `sign`. Including the deb→release two-phase fan-out and by-hash/repodata pruning.
5. **Terraform + pipeline E2E.** Modules, envs, LocalStack E2E suite.
6. **Container install verification.** Ubuntu + UBI9 suites.
7. **Seeder + cutover tooling.** `cmd/seed` (seed/verify/diff), `cmd/repoadmin retire`, cutover runbook.

## Verification

- `go test ./...` — parsers, generators against committed goldens, config mapping, EVR ordering.
- `go test -tags e2e ./test/e2e/...` — full LocalStack pipeline: upload → ingest → publish → S3 artifacts, plus the delete path.
- The two container suites are the real acceptance test: a stock `ubuntu:24.04` and a stock UBI9 install a package from the generated repository with signature verification enabled. If those pass, the index is correct in the only way that matters.
- Before cutover: `seed diff` against the live Artifactory index must show no package-level differences.

## Settled during implementation

- **`<rpm:header-range>`** — `cavaliergopher/rpm` exposes `HeaderRange()`, and it is correct: for the x86_64 fixture it returns `start=4504 end=7581`, byte-identical to what `createrepo_c` records, as are `installed` and `archive` sizes.
- **`primary.xml`, `filelists.xml` and `other.xml` are byte-identical to `createrepo_c`'s output** on both architectures, which the golden tests assert strictly. This required hand-writing the XML rather than using `encoding/xml`, which cannot emit self-closing elements, cannot control attribute order, and escapes newlines inside text.
- **`repomd.xml` cannot be byte-identical and should not be.** The compressed checksum, size and the filename derived from that checksum all depend on the gzip encoder, and Go's output differs from zlib's for identical input. The test instead asserts that `open-checksum` and `open-size` match `createrepo_c` exactly — which proves the uncompressed content is identical — and that the compressed side is self-consistent, which is what dnf actually verifies.
- **No SHA512 in `Packages`**, even though `apt-ftparchive` emits it. Records seeded from the existing index cannot have one: the live `Packages` carries only SHA1 and SHA256, and computing SHA512 would mean downloading all 3400 packages — the exact cost this design exists to avoid. Emitting it for freshly ingested packages but not seeded ones would be worse than omitting it consistently.
- **`createrepo_c` emits `<packager></packager>`, `<url></url>` and `<rpm:vendor></rpm:vendor>` unconditionally** but omits dependency sections entirely when empty. Verified against a purpose-built minimal package rather than inferred.
- **Compression must be deterministic.** gzip's header carries a timestamp by default, which would give identical content a different repodata filename on every publish and rewrite S3 needlessly.
